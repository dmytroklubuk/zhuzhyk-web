# zhuzhyk-web
Web application for Zhuzhyk online store coursework

## Запуск

Потрібні Node.js 24 і PostgreSQL із таблицями магазину. У підготовленій
хмарній конфігурації скрипт запуску налаштовує локальну базу автоматично.
Для звичайного запуску задайте `DATABASE_URL` у середовищі або в локальному
`backend/.env`.

```bash
cd backend
npm ci
npm start
npm test
```

За замовчуванням магазин працює на порту 3000. Для перевірки використовуйте
`GET /health` і `GET /items`.

## Особистий кабінет і відстеження замовлень

Перед запуском цієї версії виконайте міграцію на базі, вказаній у
`DATABASE_URL`. Вона додає акаунти, сеанси та зв’язок із замовленнями.
Для першої перевірки використовуйте локальну або тестову базу. Команду
можна повторювати.

```bash
cd backend
npm ci
npm run migrate:accounts
npm start
```

Якщо база керується через Supabase і застосунок підключається з обмеженими
правами, виконайте [SQL міграції](backend/sql/add_customer_accounts.sql)
через SQL Editor з правами на зміну схеми. Для Docker виконайте міграцію
після збірки через `docker compose run --rm app npm run migrate:accounts`
перед запуском нового контейнера застосунку. Для експлуатації в production
використовуйте HTTPS, оскільки сеансові cookie мають прапорець Secure.

Відкрийте `/account`, зареєструйтеся й оформіть замовлення після входу.
У кабінеті з’являться товари, сума, спосіб отримання та поточний етап.
Гостьові й старі замовлення залишаються доступними адміністратору.
Гостьове оформлення не потребує акаунта.

Для перевірки статусу увійдіть як адміністратор на `/admin/orders`.
Підтвердьте замовлення, позначте його готовим до видачі або відправленим
відповідно до способу отримання, а потім виконайте його. У кабінеті
покупця натисніть **Оновити**, щоб побачити зміни.

## Адмінпанель

Задайте довгий унікальний `ADMIN_PASSWORD` у середовищі процесу або в
локальному `backend/.env` і перезапустіть застосунок. Відкрийте `/admin`
і введіть ім’я користувача `admin` та заданий пароль. Для доступу з іншого
пристрою використовуйте HTTPS, оскільки вхід працює через HTTP Basic.
Docker Compose передає `ADMIN_PASSWORD` із середовища або кореневого `.env`.

У панелі можна додавати, редагувати й видаляти товари та завантажувати їхні
фотографії. Запити `POST /items`, `PATCH /items/:id` і `DELETE /items/:id`
потребують облікових даних адміністратора та заголовка `X-Admin-Request: 1`.

### Спільні фото товарів

Фото, завантажені через адмінпанель, зберігаються в PostgreSQL разом із
каталогом. Усі екземпляри застосунку, підключені до тієї самої бази через
`DATABASE_URL`, показують ці фото автоматично.

Перед запуском нової версії виконайте `npm run migrate:photos` у папці
`backend` (у PowerShell також можна використати `npm.cmd run migrate:photos`).
Команда створює таблицю та переносить фото з `backend/uploads/products`
із збереженням наявних адрес. Запустіть її на кожному комп’ютері, де є
оригінальні файли. Якщо файл втрачено, завантажте фото повторно через адмінпанель.

Для Docker виконайте `docker compose run --rm app npm run migrate:photos`
після збірки. Щоб перенести фото з локальної інсталяції, запустіть міграцію
там, де лежать файли, з тим самим `DATABASE_URL`.
